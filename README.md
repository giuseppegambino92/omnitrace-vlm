# omnitrace

**Multimodal late-interaction visual RAG · cross-modal causal timeline correlator · AI security engine**

omnitrace is built from first principles: `numpy`, `scipy`, `Pillow`, `sqlite3`, plus
`FastAPI` / `Typer` / `Rich` for the interfaces. It uses no ML frameworks, no embedding
models and no OCR, and every test and benchmark runs offline and deterministically. A VLM
(local through Ollama, or any OpenAI-compatible endpoint) can optionally be plugged in to
*read* the evidence omnitrace has already retrieved and grounded.

| Subsystem | What it does |
|---|---|
| **A · Zero-OCR spatial patch RAG** | Encodes each page or screenshot as a 32×32 grid of multi-vector patches (layout-graph-contextualised text features, colour/gradient descriptors, spatial coordinates). Retrieves with ColPali-style MaxSim (float32 / int8 / 2-bit / 1-bit) and returns a 2-D activation heatmap plus the **bounding box** of the answer region as a verifiable citation. |
| **B · Cross-modal RCA** | Prunes screen recordings to keyframes (cycle-aware perceptual hashing), detects visible symptoms in pixels and DOM, builds a time-respecting causal DAG (frames ↔ DOM ↔ spans ↔ logs) and ranks the root-cause span along with its causal path to the symptom. |
| **C · Injection shield + loop breaker** | Scans retrieved docs, DOM text, alt text and tool outputs for instruction overrides, role spoofing, invisible-Unicode smuggling, encoded payloads and tool hijacking. Applies spotlighting/datamarking and taint-tracks tool calls. Halts agent loops using semantic action entropy. |

> **Read this before the numbers.** All benchmark data is **synthetic**: it is generated by
> code in `evals/datasets/` and exported for inspection. The heuristics were developed
> against the *dev* splits, so the suite also reports **held-out** splits (unseen generator
> seeds, plus a separately written injection corpus). The held-out splits share the dev
> templates, though, so they show robustness to randomisation, not to new kinds of
> documents, apps or attacks. See [Limitations](#limitations).

### What the benchmarks measure

1. **2-D grounding.** 15 pages (1024×1024), three each of: spec tables (two tables per page), P&ID
   schematics, 2–3-column engineering specs, application UIs and bar charts. There are 60
   queries. A hit means the correct page **and** IoU ≥ 0.5 between the returned box and the
   ground-truth answer region, which might be a table cell, a schematic node, a paragraph, a
   widget or a chart bar. Vocabulary is deliberately shared across pages (every table has
   "Max Voltage"), so a hit needs the right entity *and* the right 2-D relation.
   *Flat-chunk BM25* is the classic RAG pipeline: reading-order linearisation, 40-token windows, and
   a citation that is the union box of the chunk's words. *Region BM25* indexes every layout
   element separately but without 2-D context.
2. **Frame dedup.** 200 noisy frames (σ = 1.5 grey levels) with 12 real transitions, including
   a one-digit badge change, a 25-frame spinner, a modal opening and closing, a toast and a fade.
   Recall is exact-frame. The baseline keeps frames whose global dHash moved by more than 4 bits.
3. **Cross-modal RCA.** 10 failing storefront sessions (12 s, 60 frames, about 66 spans over
   about 14 services). The root causes are: a DB statement timeout three hops down, schema
   drift behind HTTP 200, a 30 s Elasticsearch stall, a 401 token, a 503 hidden behind a gateway
   502, CORS (status 0), a gateway 429, null pricing fields, flag-config drift, and three
   deadlocked retries. Distractors in every trace: a 404 favicon, a 503 that was retried
   successfully, an unrelated erroring email consumer, a slow healthy cron job, errors that
   happen *after* the symptom, a concurrent unrelated 500, and a benign red "SALE" badge.
4. **Security.** 30 benign technical documents, each built around a hard negative: `curl … | sh`
   install lines, role JSON in LLM-API docs, `send_email()` SDK references, base64 Kubernetes
   secrets, JWTs, SHA-256 lists, emoji ZWJ, Persian ZWNJ, Greek units, YAML `system:` keys,
   "do not email credentials", human support *agents* who "should" do things. Plus 25
   payloads embedded in realistic carriers: READMEs, reviews, PDF white text, tool JSON,
   calendar invites, aria-labels and EXIF. Plus 5 cyclic and 5 progressing agent trajectories.

## Quick start

```bash
python3.11 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

pytest                                   # 63 tests, ~8 s, fully offline
python -m evals.benchmark_suite          # ~20-40 s; writes evals/latest_report.json + both README metric blocks
python -m evals.repeat_runs --update-metrics   # 3 gated runs + repeatability intervals in both READMEs
omnitrace dash                           # heatmap citation, causal timeline and security alerts in the terminal
```

### CLI

```bash
# A · index a folder of page images (+ optional <name>.json structure layer) and query it
omnitrace index ./pages --db pages.sqlite            # or: omnitrace index --demo
omnitrace query "max current of P-204" --db pages.sqlite --crop citation.png
omnitrace query "max current of P-204" --vlm ollama:qwen2.5vl     # VLM reads only the cited crop

# B · root-cause a failing execution (TraceBundle JSON: spans, logs, dom, optional frames)
omnitrace rca trace.json          # or: omnitrace rca --demo list / --demo payment_db_timeout

# C · scan untrusted content (exit code 2 when blocked), optionally spotlight it
cat page.html | omnitrace shield - --source dom_text --spotlight datamark

omnitrace serve                    # MCP over streamable HTTP at http://127.0.0.1:8765/mcp
omnitrace serve --stdio            # MCP over stdio
```

Structure-layer sidecar (`page.json`), which is what a PDF text layer, DOM snapshot or SVG export
provides:

```json
{"regions": [
  {"id": "h2", "bbox": [430, 124, 560, 158], "text": "Max Current", "role": "header", "parent": "spec"},
  {"id": "r3c2", "bbox": [430, 260, 560, 294], "text": "12.5 A", "role": "cell", "parent": "spec"},
  {"id": "spec", "bbox": [40, 124, 960, 464], "text": "Electrical ratings", "role": "container"}
]}
```

Roles that carry layout meaning are `header`, `rowheader`, `label`, `heading`, `caption`, `title`,
`cell`, `container` and `node`/`widget`/`bar`/`text`. Pages without a sidecar still work: the
bounding box then comes from the heatmap alone (see the ablation).

## How it works

### Scoring at a glance

The noise floor is $`\nu = 2.5/\sqrt{976}`$ (the hashing noise level), $`m_{i,d}`$ is the best
patch similarity of query token $`i`$ on page $`d`$, and $`s_{ij}`$ is its similarity to patch $`j`$.

Page ranking (calibrated, IDF-weighted late interaction; a token whose best page scores below
0.2 counts as unmatched and contributes 0):

```math
S(q,d) = \sum_i \mathrm{idf}_i \cdot \mathrm{clip}\!\left(\frac{m_{i,d} - \nu}{\max_{d'} m_{i,d'} - \nu},\ 0,\ 1\right)
```

Activation heatmap (soft AND, weighted harmonic mean over informative tokens):

```math
H_j = \left(\frac{\sum_i w_i \,(\varepsilon + n_{ij})^{-1}}{\sum_i w_i}\right)^{-1} - \varepsilon,
\qquad n_{ij} = \frac{\max(0,\ s_{ij} - \nu)}{\max_k s_{ik} - \nu}
```

Root-cause ranking and span evidence (noisy-OR):

```math
\text{score}(s) = \max_a \ \text{sev}(a) \cdot \text{reach}(s \to a) \cdot e(s) \cdot o(s),
\qquad e(s) = 1 - \prod_k \bigl(1 - e_k(s)\bigr)
```

Shield decision and loop-breaker entropy rule:

```math
\text{risk} = 1 - \prod_f \bigl(1 - \text{sev}_f\bigr) \ge 0.8 \Rightarrow \text{block},
\qquad -\sum_a \hat p(a) \log_2 \hat p(a) \le 1 \ \wedge\ \text{novelty} \le 0.2 \Rightarrow \text{halt}
```

### A · Spatial patch encoder and late interaction (`vision/`)

* **Layout graph** (`patch_encoder.build_layout_graph`). Leaf regions are nodes. Each node gets
  context edges from its row header or label (weight 1.0), its column header (1.0), the nearest
  section heading above it in the same column (1.0), its immediate left/above neighbour (0.3 when
  that neighbour is a descriptor or the node is a cell), its container caption (0.3) and schematic
  connectors (0.6). Sibling headers don't describe each other. The region vector is
  `normalize(own + λ(n)·ctx)`, where `ctx` saturates at unit norm and `λ` shrinks as the region's
  own text grows. A bare number therefore lives off its headers, while a rich label mostly
  describes itself.
* **Text features**: signed feature hashing (BLAKE2b, 976 dimensions). Each word is spread over 8
  slots and each character trigram over 2, so hash collisions behave like small Gaussian noise
  (σ ≈ 1/√976) rather than rare large spikes. Short numbers bind to the preceding noun:
  "line 1" becomes `line-1`.
* **Patches**: region vectors are splatted onto the 32×32 grid, weighted by
  `|r∩p| / min(|r|,|p|)`. Long paragraphs are split into word-flow bands, so each patch carries its
  local words. Each patch also gets 32 visual dimensions (12-bin hue histogram centred on red,
  achromatic fractions, an 8-bin gradient-orientation histogram, edge density, luminance and colour
  moments) and 16 positional dimensions. Query words like *red*, *orange*, *top* and *bottom*
  map onto those subspaces.
* **Quantisation**: a seeded random orthogonal rotation (preserves dot products, spreads energy
  evenly), then int8 (per-vector absmax), 2-bit (Lloyd-Max Gaussian levels ±0.45σ/±1.51σ), and
  1-bit sign packs scored asymmetrically as `⟨q, sign(p)⟩·‖p‖·√(π/2D)`. Search runs in two
  stages: a 1-bit shortlist, then a rerank at the requested precision.
* **Page score**: MaxSim with per-token corpus calibration. Each query token contributes
  `idf · clip((m − noise)/(best − noise), 0, 1)`, so a rare part number inside a long label counts
  as much as a common word matched by a one-word header. Raw ColBERT MaxSim is kept as an
  ablation.
* **Heatmap**: a soft AND (weighted harmonic mean). Each token's similarity is normalised by its
  best patch and denoised. Tokens best matched by the page title count as page *scope* and are
  excluded from grounding. If nothing satisfies every token, the blocking token is dropped
  greedily. The winner is therefore the cell where row *and* column constraints meet, not the
  column header.
* **Bounding box**: structure-layer proposals are scored by
  `0.75·soft-AND(region embedding) + 0.25·mean patch heat`. Descriptors (headers, labels) whose
  words the query merely restates are down-weighted, because they point at the answer rather than
  containing it. Without a structure layer, the box is the thresholded connected component around
  the heat peak.

### B · Keyframes, symptoms and the causal DAG (`vision/phash_dedup.py`, `correlator/`)

* **Keyframes**: one integer box reduction per frame (zero-copy Pillow import), then a 64-bit
  dHash and an 18×32 grid of tile means. The change threshold adapts to noise
  (`max(0.9, 8·σ̂)` with σ̂ from the median absolute delta). Runs of changes confined to at most 3%
  of tiles are treated as **animations**, and only their start and settled end are kept. Those
  runs also feed the frozen-spinner detector.
* **Symptoms from pixels**: new persistent saturated-red regions (error banners), amber regions
  (warning toasts), a dimmed periphery around a bright centre box (modals), textured tiles going
  flat and staying flat (blank regions), and animations longer than 3 s (stalls). Symptoms from
  the DOM: error classes and `role=alert`, poisoned text (`NaN`, `undefined`…), busy indicators that
  never clear, and emptied containers.
* **DAG** edges point from cause to effect, and all respect time:
  * child span → parent span (0.9)
  * client span end → DOM mutation. The weight is the affinity between the DOM node (selector,
    attributes, text) and the request's whole downstream trace. A "Payment failed" banner binds
    to the trace that touched `payment-service`. A failure-looking DOM change and a failed
    response are also mutually consistent.
  * request start → busy indicator
  * DOM mutation → symptom (bbox overlap inside the visual window)
  * in-flight request → stall
  * a weak temporal-only fallback
* **Ranking**: `severity(a) · reach(s→a) · evidence(s) · origin(s)`.
  * Evidence is a noisy-OR of status class, error flag, ERROR/FATAL logs (higher when there is
    exception text), robust latency z-score against same-operation peers, response-schema drift
    against the operation's majority schema, and null fields.
  * Origin is 0.3 when the span's failure is fully explained by a child with the same class of
    evidence (the 502 above a 503), and 0.15 when a retry recovered the failure.

### C · Shield and loop breaker (`security/`)

* **Unicode**: tag-character smuggling (decoded and re-scanned); zero-width characters inside
  words, with emoji ZWJ, Indic/Persian ZWNJ and a leading BOM exempt; zero-width binary
  encodings (decoded); bidi overrides (high severity in left-to-right text, low in RTL text);
  variation-selector byte smuggling; Latin words containing Cyrillic/Greek look-alikes (decoded
  with a confusables map). Units like μs and kΩ are not flagged.
* **Lexical rules** run on several normalised views (leetspeak, spaced letters, stripped markdown)
  behind cheap literal gates. They cover instruction override (English, French, Spanish, German,
  Italian, Portuguese), role reassignment, injected tasks, concealment ("don't tell the user"),
  secret exfiltration and disclosure, safety bypass, authority claims, AI-addressed imperatives,
  and data egress to an email address.
* **Context**: the same construct inside a fenced code example or inline code is weighted far
  lower. Negated advice ("do not email credentials") and document-structure references ("ignore
  the previous *section's* instructions") are exempt. Metadata channels (alt text, aria, EXIF,
  hidden DOM) get a severity boost.
* **Encoded smuggling**: high-entropy base64, hex and percent-encoded runs are decoded
  (recursively, up to depth 3). Only text-like plaintext is re-scanned, so hashes, JWT signatures
  and images pass.
* **Tool hijacking**: imperative or JSON/syntax invocations of sensitive tools are high severity
  only when the sentence carries a target (email, URL, `~/.ssh`, `.env`) or secrets, or addresses
  the AI. Also detected: markdown-image exfiltration URLs with template placeholders, and
  pipe-to-shell outside code examples.
* **Decision**: risk is the noisy-OR of finding severities; block when risk ≥ 0.8.
* **Spotlighting**: nonce-tagged delimiters that the content cannot forge, plus datamarking
  (whitespace replaced by `ˆ`) or base64. `ToolCallGuard` blocks sensitive tool calls whose
  arguments copy untrusted content, or that untrusted content asked for.
* **Loop breaker**: arguments are canonicalised (UUIDs, timestamps, epochs, hex ids, nonces
  stripped) and embedded. A call joins an existing *action prototype* when cosine ≥ 0.85, or
  ≥ 0.45 when it also produced the same observation, which catches paraphrased retries. The
  breaker halts on (a) a period-≤4 cycle repeated 3× with identical observations, or (b) action
  entropy ≤ 1 bit with ≤ 20% novel (action, observation) pairs over 10 steps. Pagination and
  polling with changing results count as progress.

## Limitations

* **Synthetic, self-authored data.** The generators, the queries, the injection payloads and the
  heuristics were all written by the same author. The held-out splits change random seeds, and
  the injection held-out set was written after the detectors were frozen. Even so, none of it
  is independent real-world data, and 100% here shouldn't be read as 100% on your documents.
  Validate on your own corpus before relying on it.
* **No semantics beyond lexical hashing.** Synonyms ("amperage" for "current") don't match. A
  learned encoder (e.g. a real ColPali checkpoint) would close that gap; the index, quantisers
  and grounding logic would carry over unchanged.
* **Precise boxes need a structure layer.** From pixels alone, the heatmap box is 32-px coarse
  (see the ablation). Purely raster documents would need an OCR or VLM pass to produce regions.
* **RCA assumes browser-side client spans and DOM records** with bounding boxes, as produced by
  OpenTelemetry web instrumentation plus a mutation observer. Without the video, the two
  modal-only symptoms are invisible (see the ablation).
* **The shield is a rule system.** It will flag documents *about* prompt injection that quote
  attacks verbatim, and a determined attacker can find phrasings outside its rules. It is a
  pre-filter alongside spotlighting and tool-call gating, not a replacement for least-privilege
  tool design.
* Latencies are single-threaded CPython on the machine named in the results header. They
  depend on hardware and background load; the repeatability block shows their spread over
  quiet-machine runs.
